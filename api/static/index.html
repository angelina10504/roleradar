Ingestion volume

Rows processed per run, not rows available upstream. The n8n Limit node caps each run — currently at 5 — so a flat line at the cap is the cost control working, not the feed drying up.

Extraction success rate

Validated ÷ ingested per run. At five rows per run one rejection is a 20-point swing, so the 3-run rolling mean is plotted beside it.

Rejection reasons

Dead-lettered postings by error code, coloured by category.

Model disagreement rate

How often the model's mentions_n8n disagreed with /\bn8n\b/i over the description. A floor, not an exact rate.

Recent runs

Newest first. Δ is the change in success rate from the previous run.

Ingested means processed, not available. It counts what the pipeline put through the model, not what Remotive had — DEV_JOB_LIMIT caps each run, currently at 5. Runs recorded before that cap was set can exceed it.

Rejection reasons count rows by default: how many postings carry the code. Occurrences counts entries in errors_json, so one row with three bad enums counts three times. The two differ and the toggle says which is on screen.

This page cannot see infra failures. A run that died before writing to Postgres leaves no rows, so it is not a run here at all. The recent-runs table will look clean through an outage; a stale "since last run that produced data" is the only signal.
